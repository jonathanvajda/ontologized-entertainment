# RDF Parsing and Serialization Inventory

## Capability Family

- **Capability family:** RDF parsing and serialization
- **Survey date:** 2026-07-27
- **Survey owner:** Codex
- **Apps surveyed:** OntoEagle, tabular-ontology-maker, axiolotl, visual-lynx, ontology-curation-manager / Ontology Compliance Diagnostic, ontology-tabulator, iri-swapper, table-nova
- **Apps with no relevant implementation:** IRI Swapper SPARQL page has SPARQL text handling but no generic RDF parser or serializer candidate.

## Scope

This inventory covers functions that parse RDF text into RDF/JS-like stores, rdflib graphs, N-Quads text, or JSON-LD graph objects, plus functions that serialize RDF stores/datasets/quads back to Turtle, TriG, N-Triples, N-Quads, JSON-LD, or RDF/XML.

Browser file reading, download triggering, MIME lookup, prefix registry lookup, tabular parsing, ontology-specific row mapping, and SPARQL parsing are adjacent capabilities and should remain outside the core RDF I/O package.

## Survey Notes

- `ontology-curation-manager/docs/app/rdf-io.js` is the cleanest package-ready source because it already has JSDoc, runtime-library injection, format normalization, parser dispatch, serializer dispatch, and term conversion helpers.
- `visual-lynx/docs/app/linked-data-transformer-core.js` is the broadest behavior source and has the best format-transform workflow. Its logging and RDF/XML repair behavior should be evaluated as optional behavior for the canonical package.
- `table-nova/docs/app/rdf/serialize.js` is the strongest small serializer module, especially for multi-format export from a dataset. Its module-load global checks should be replaced with explicit runtime injection before promotion.
- `iri-swapper/docs/app/ont-iri-swapper.js` contains important named-graph ingest and export behavior, but that behavior is workflow-specific and should become a thin adapter around shared parser/serializer functions.
- `axiolotl` mixes RDF parsing/serialization with IndexedDB, Comunica, and workspace graph state. The pure serializer parts are useful references; storage-coupled functions should not move into `rdf-io`.
- `tabular-ontology-maker` has useful N3 and JSON-LD parsing/serialization snippets, but most candidates are embedded in a large UI/workspace file.
- OntoEagle's `rdf_io.js` is compact and easy to adopt but less mature than OCM/Visual Lynx because it returns a bare store and does not preserve structured warnings/prefix metadata.
