## Survey Notes

- This milestone should be renamed from extraction to read/write and IRI provisioning.
- OntoEagle is the strongest reader/display source; TOM is the strongest writer/provisioning source.
- Metadata record shapes should use full IRIs from `COMMON_NAMESPACE_IRIS` internally. Compact CURIE keys are a serialization concern.
- DCTERMS/DC/RDFS/SKOS/OWL terms remain canonical for common ontology metadata. OKEA is only for uncovered knowledge-engineering artifact predicates.
- URL predicates now needed by this milestone are registered as OKEA namespace terms: `hasGitRepositoryUrl`, `hasIssueTrackerUrl`, `hasOntologyDownloadUrl`, and `hasQualityAssuranceReportUrl`.
- Generation provenance predicates now needed by this milestone are registered as OKEA namespace terms: `hasGeneratingSoftwareApplicationName` and `hasGenerationRunIdentifier`.
- Table-Nova is the downstream writer test: generated TBox and combined RDF receive ontology declaration and standard metadata without hand-rolled metadata triples; ABox-only output remains unchanged.
- `dcterms:format` values are MIME types, not labels or extensions.
- `dcterms:source` values are privacy-safe local filenames, not full local filesystem paths.
- Canonical records use `@id` for the ontology IRI. `dcterms:identifier` is not used as a duplicate ontology IRI.
- TOM's former local IRI policy fields should migrate to OKEA predicates, including base IRI, delimiter, opaque/readable mode, opaque prefix, integer width, integer start, local-name style, version token strategy, and version insertion position.
