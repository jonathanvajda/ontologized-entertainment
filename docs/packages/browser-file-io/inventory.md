# Function Inventory

## How to Fill This Out

This file is the capability-cycle inventory for the third capability family: Browser file/download utilities. It follows the roadmap's Phase 1.5 candidate fields and records discovered functions without changing application code.

## Capability Family

- **Capability family:** Browser File I/O and Downloads
- **Survey date:** 2026-07-26
- **Survey owner:** Codex
- **Recommended package path:** `monorepo-staging/packages/browser-file-io/`
- **Target package shape:** `src/read-file-as-text.js`, `src/read-file-as-array-buffer.js`, `src/create-text-blob.js`, `src/download-blob.js`, `src/download-text-file.js`, `src/create-accept-attribute.js`, `src/index.js`, `test/`, `fixtures/README.md`, `contract.md`, `migration.md`, `decision-log.md`
- **Apps surveyed:** OntoEagle, tabular-ontology-maker, axiolotl, visual-lynx, ontology-curation-manager, ontology-tabulator, iri-swapper, table-nova
- **Apps with no relevant implementation:** None. Every surveyed repository contains file reading, download, or both.

## Survey Notes

- The strongest browser text reader is Table Nova `docs/app/io/fileReaders.js` because it preserves `reader.error`, catches setup exceptions, and has JSDoc.
- The most broadly adopted download implementation originally lived in `browser-file-actions.js` under `format-registry`; it now belongs to `packages/browser-file-io`.
- A clean canonical package should separate pure filename/MIME helpers from browser side effects. MIME detection can remain in `format-registry`; Blob creation and anchor clicking belong here.
- Several modern code paths use `file.text()` directly. These are concise and reasonable, but a package-level `readFileAsText` can centralize error shaping and fallback behavior.
- Inline app workflows should not be promoted wholesale when they combine file reading with parsing, storage, UI state, or confirmation dialogs.
