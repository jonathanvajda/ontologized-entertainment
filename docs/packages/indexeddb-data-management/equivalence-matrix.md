## Difference Classification

|Difference ID|Candidates affected|Description|Classification|Decision|Rationale|
|:---|:---|:---|:---|:---|:---|
|DIFF-001|Axiolotl graph store vs run stores|Graph data needs indexed quad rows; run stores need opaque payload records.|Legitimate option|Split `quad-store` from generic `artifact-store`.|Combining them would create a broad, unclear API.|
|DIFF-002|OntoEagle built-in vs user datasets|Built-in data is preloaded and refreshed by fingerprint; user data is imported and toggleable.|Legitimate option|Make dataset `source` and `enabled` first-class fields.|Search/seed/slim depend on merged enabled dataset workspace.|
|DIFF-003|TOM latest-session model vs OCM/IRI/Table Nova run history|Some apps resume one active project; others list prior runs.|Legitimate option|Support both `lastPointer` and history listing in shared run store.|A single API can support both without forcing UX uniformity.|
|DIFF-004|Native IndexedDB wrappers vs `idb` package|Apps mix callback wrappers and `idb.openDB`.|Accidental divergence|Choose one adapter style for shared package; likely small native promise wrapper or `idb` adapter with explicit provenance.|Migration should not expose raw IDBRequest handling everywhere.|
|DIFF-005|Storage functions dispatch DOM events|Axiolotl storage emits `CustomEvent`s.|Boundary violation|Move notifications into app adapter callbacks or event bus wrapper.|Storage core should be reusable outside DOM.|
|DIFF-006|LocalStorage companion caches|OntoEagle snapshots, registry overrides, theme/prefix settings use localStorage.|Legitimate adapter|Classify as `browser-key-value-store`, not IndexedDB core.|Some data is cache or preference, not durable project data.|
|DIFF-007|Mermaid FSA support|Mermaid can store projects in browser storage or a user-selected folder.|Improvement|Use as optional backend pattern after IndexedDB project model stabilizes.|File-backed project portfolios are relevant but should not block IDB package.|

## Canonical Behavior Recommendation

- **Recommended canonical behavior:** Define a layered storage model: pure record schemas and ID creation; IndexedDB adapter; project store; artifact store; dataset store; quad store; app settings store.
- **Behavior to preserve as options:** Built-in vs user dataset source; latest pointer; run history; default graph vs named graph; folder-backed project backend.
- **Behavior to reject:** DOM events from storage core, app-global hard-coded DB names in promoted functions, “one giant persistence function” that parses, transforms, renders, and stores.
- **Behavior requiring migration notes:** Axiolotl default graph as empty string, TOM RDF fallback records, OntoEagle localStorage ontology snapshots, IRI Swapper duplicate run stores.
- **Open questions:** Whether all RDF project artifacts should be stored as quads with default graph represented by `null`, empty string, or RDF/JS `DefaultGraph`; whether binary source files should be stored in IndexedDB, OPFS, or only as metadata plus File System Access handles.
