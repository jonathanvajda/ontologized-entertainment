## Survey Notes

- OntoEagle is the strongest example of preload/user dataset distinction. It treats built-in graph data and user-imported ontology data differently while exposing one enabled-documents workspace to search, catalog, viewer, and slim generation.
- Axiolotl is the strongest graph-store example. It already needs graph rows, named/default graph distinction, saved queries, app settings, granular deletion, and workspace status events.
- TOM is the strongest single-project app model. It has one ontology workspace with settings, imports, predicates, axioms, rows, and RDF fallback.
- OCM, IRI Swapper, and Table Nova are run-history examples. They store “you ran this before” artifacts rather than durable project state.
- Mermaid is the strongest project/artifact model: projects contain diagrams, and storage can be IndexedDB or File System Access. Its concept/storage split is more mature than most current app storage code.

## Mermaid Reference Benchmark

Mermaid should be treated as a reference implementation for project and nested artifact management, not as a direct source of ontology-specific storage code.

- It gives this capability family a concrete benchmark for project CRUD, nested artifact CRUD, rename/delete flows, and persistence tests.
- It demonstrates a clean backend boundary: project/diagram operations sit above IndexedDB or File System Access implementation details.
- It raises the target maturity for promoted project/artifact storage functions because project management is already tested and user-facing there.
- It should influence the shared contract for `ProjectRecord`, `ArtifactRecord`, `createProject`, `listProjects`, `storeProjectArtifact`, and `deleteProjectArtifact`.
- It should not determine RDF graph storage semantics. Axiolotl and OntoEagle remain the better reference apps for quads, named/default graph handling, ontology dataset preload, and user-imported ontology state.
