# Function Inventory

## Capability Family

- **Capability family:** YAML, HTML, and print export
- **Survey date:** 2026-08-10
- **Survey owner:** Codex
- **Apps surveyed:** OntoEagle, ontology-curation-manager / Ontology Compliance Diagnostic, ontology-tabulator, tabular-ontology-maker, axiolotl, visual-lynx, sparql-pattern-visualizer, table-nova, iri-swapper
- **Apps with no relevant implementation:** tabular-ontology-maker, table-nova, iri-swapper, sparql-pattern-visualizer, visual-lynx
- **Apps with adjacent but not directly promotable implementation:** axiolotl has HTML query-result rendering, but no YAML/HTML report export or print workflow.

## Scope Notes

This inventory covers document/report-oriented serialization and printing:

- YAML report serialization.
- HTML report serialization.
- Print-friendly document/window creation.
- Table/document export actions where the output is intended for user inspection rather than RDF/tabular interchange.

This inventory does not re-inventory already promoted RDF, tabular, browser-file-IO, or format-registry behavior except where current code couples those concerns to report export.

## Survey Notes

- OCD is the only app surveyed with mature YAML and full HTML report export examples.
- OCD measures has parallel YAML/HTML export logic that should be consolidated with the main report export pattern.
- Ontology Tabulator has useful print-window behavior, but the current `printTableOnly` function copies live DOM and has weak escaping/validation. It is a good adapter candidate after hardening.
- OntoEagle ontology viewer has print/export through Tabulator vendor APIs. This should be wrapped only if we need a stable cross-table-library print/export API.
- Axiolotl has HTML rendering for SPARQL result previews, but not a report export/print feature. It should be considered adjacent input to later report-table rendering, not a primary candidate for this milestone.
- The current shared format registry already includes `text/html`; YAML is not currently registered in the shared `format-registry`, so promotion should add YAML descriptors before replacing hard-coded `text/yaml;charset=utf-8` values.
- The current shared browser-file-IO package should remain responsible for Blob/download side effects. The report-export package should serialize report content and construct export descriptors.
- Tests exist for OCD report/measures serializers, but they are mostly smoke tests. Promotion should add golden-output tests, HTML escaping tests, YAML scalar/list edge cases, empty-report behavior, and injected print-window behavior.
