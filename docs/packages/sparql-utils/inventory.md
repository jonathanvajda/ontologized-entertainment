## Survey Notes

- IRI Swapper has the strongest pure SPARQL IRI rewrite implementation. It is already close to reusable but needs a change-log output and stronger tests before promotion.
- SPARQL Pattern Visualizer has the strongest AST-to-graph analysis, but that should probably split between SPARQL parsing utilities and a later visualization capability family.
- Axiolotl has the broadest SPARQL execution surface: local workspace, named graph, endpoint, CONSTRUCT preview, UPDATE preview, saved-query artifact handling, and prefix UI. Much of this should become adapters over smaller promoted pure utilities rather than one large promoted package.
- OCM has the cleanest SELECT/ASK Comunica execution functions. These are good candidates when the cycle reaches execution adapters.
- `tabular-io/query-records.js` already covers generic SQL/SPARQL/NoSQL query record import/export. Do not re-promote that into SPARQL-utils.
- `format-registry` already covers SPARQL MIME/extension descriptors. Do not duplicate format decisions here.
- `namespace-registry/sparql-prefixes.js` already contains SPARQL prologue helpers. During promotion, decide whether those stay under namespace-registry or move into a new SPARQL-focused package that imports namespace-registry.
